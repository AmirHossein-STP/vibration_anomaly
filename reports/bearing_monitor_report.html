Vibration anomaly detection · session of 22 October 2026

Bearing Monitor Report

This session started with one question about a rented server and ended with a bearing monitor that was tested on ten public datasets and then sat a sealed final exam. This page explains every step: what we built, what we measured, what passed, what failed, and why.

1. The short version

You asked for two things, in this order:

  1. Set up the rented server once, cleanly, so every future rental is quick, and put the datasets on the permanent storage volume, downloaded directly, not through your laptop.
  2. Then run the research plan yourself, without asking, and later, make the system work on many bearings.

What works

  • One command (remote/box up <ip>) readies a new rental in about 30 seconds. Data and results live on the permanent volume.
  • The detection score works across machines and bearing sizes it was never tuned on:
    • Ottawa 2018: AUC 0.92–1.00;
    • MFPT: 1.00;
    • HUST: 4 of 5 bearing types;
    • on the sealed IMS exam it rises to 0.88–0.97 on all four bearings that failed.
  • Comparing each bearing with its own healthy history is much better than comparing it with other bearings.
  • A product exists: the bearing service monitors a fleet of units, each with its own baseline.

What does not work yet

  • The trend alarm, which watches for a slow rise across recordings, gave about one false event per day on healthy bearings during the final exam. It also fired on healthy units, so the pre-registered verdict was not consistent.
  • Ball and cage faults are mostly missed.
  • Saying which race failed is right most of the time, but not reliably. It is reported as a hint.
  • Every machine needs a speed signal. Guessing speed from vibration was tested and is not good enough.
  • No real machine data has been tested. Everything here is laboratory data.

4. Building the server system

4.1 The problem

You rent two things from the provider:

  • a compute server (RTX 3090, 8 cores, 30 GB RAM, 100 GB SSD), which exists for a few hours and is then deleted completely;
  • a 32 GB storage volume that is permanent and can be attached to any future server.

Earlier rentals were set up by hand. That cost time each time, and once, results were lost when a server was deleted. The aim was one system, set up once and written down, so every later rental takes minutes.

5. How the method works, in plain words

5.1 The ideas

A damaged bearing makes a small knock every time a ball rolls over the damage. The knocks repeat at a rate set only by the bearing's shape and the shaft speed. If we measure that rate in multiples of shaft speed ("orders"), it is the same number on any machine running that bearing at any speed. That is why the method can move from machine to machine where neural networks trained on one machine could not.

flowchart TD
  s["Vibration recording + shaft speed"] --> r["Resample to 12 kHz"]
  r --> w["Cut into 1 s windows (overlap 0.5 s)"]
  w --> c["Flatten the spectrum (cepstrum pre-whitening)<br/>removes the machine's own resonances"]
  c --> e["Squared envelope<br/>keeps the knock rhythm, drops the carrier"]
  e --> o["Envelope spectrum, read in orders of shaft speed"]
  o --> L6["Six fault lines<br/>BPFO and BPFI × 1, 2, 3<br/>(needs bearing geometry)"]
  o --> G["135 bins from 1.5 to 15 orders<br/>(geometry-free, v1.1 detector)"]
  L6 --> T["Typing hint:<br/>which race rose most"]
  G --> Z["Each value as a z-score against<br/>the unit's OWN healthy windows"]
  L6 -.->|v1.0 detector| Z
  Z --> M["Window score = largest z"]
  M --> TH["Threshold = cross-fitted conformal quantile (10%)"]
  TH --> V["Recording verdict:<br/>healthy · watch ≥ 40% · faulty ≥ 50% of windows"]
  s --> LV["Level: log RMS per recording,<br/>adjusted for speed and load"]
  LV --> CU["CUSUM trend alarm across recordings"]

Orders

Frequency divided by shaft speed. At 900 rpm (15 Hz) a fault at 3.05 orders sits at 45.8 Hz; at 1500 rpm, at 76.3 Hz. In orders it is the same 3.05.

BPFO, BPFI, BSF, FTF

The four fault rates: outer race, inner race, ball spin, cage. All come from ball count, ball diameter, pitch diameter and contact angle. A check that always holds: BPFO + BPFI = number of balls.

Envelope

The knocks ring the machine's structure at high frequency. The envelope follows the loudness of that ringing, so the knock rhythm appears as clean lines in its spectrum.

CPW + SES

Cepstrum pre-whitening flattens the spectrum, so no frequency band has to be chosen by hand. The squared envelope spectrum (SES) then shows the rhythm. It needs no tuning, so it cannot be tuned to fault labels.

Healthy baseline, z-score

For each line or bin we learn its usual value on that unit's healthy windows. A new window's z-score says how many standard deviations above usual it is. Only rises count.

Max over lines

A fault usually lights one or two lines, not all of them. Taking the largest z catches that, and averaging would dilute it (tested in WP3).

Conformal threshold

Pick the threshold so that about 10% of healthy windows exceed it. With enough healthy data this rate is guaranteed on new healthy windows from the same unit.

Cross-fitting

Each healthy recording is scored by a baseline built without it. Without this, small baselines judge themselves too kindly and false alarms overshoot (found in WP5).

Geometry-free bins

Instead of six named lines, read 135 small bins across 1.5–15 orders. It needs no geometry, and it turned out to detect better (WP13–WP15).

Order tracking

When speed changes inside a recording, the envelope is resampled to equal steps of shaft angle using the encoder. Fault lines then stay sharp (Ottawa 2018).

Typing

If the bearing is known: did the outer-race lines or the inner-race lines rise more? Reported as a hint.

CUSUM trend alarm

Adds up how much each recording sits above normal, minus a small allowance. A slow, steady rise builds up until it crosses a limit. Single noisy recordings do not.

5.2 How we judge results

Recall

Share of faulty windows that are flagged. Higher is better.

False alarm (FA)

Share of held-out healthy windows that are flagged. The target is 10%. We always report the worst unit too, because false alarms are usually caused by one odd unit.

AUC

If you pick one faulty and one healthy window at random, AUC is the chance the faulty one scores higher. 0.5 is a coin toss and 1.0 is perfect. It does not depend on any threshold.

Held-out folds

We never test on what was used for calibration. Typically we hold out one healthy unit or recording at a time and repeat.

Pre-registration

Before every experiment the question, the protocol and the pass rule were written into a notes file and committed. Then it ran. Several rules failed, and we kept the failures.

Seen vs unseen data

Once a dataset has influenced a choice it is "spent" for confirming that choice. Real confirmation needs data nobody has looked at. IMS was kept sealed for the final exam.

WP7Run to failure: XJTU-SY

Fifteen bearings ran until they broke, with one recording per minute. Each bearing's first 20 minutes served as its healthy baseline.

  • Typing at end of life was right on 10 of 11 single-race failures: physics names the failed race on real, naturally grown damage.
  • The raw per-minute physics score is noisy. A simple "3 minutes in a row above the threshold" alarm fired later than a plain RMS alarm on most bearings. That pre-registered check was does not support.

So we built a proper decision layer: smoothed statistics (EWMA, CUSUM) with the threshold set from healthy minutes of other bearings, allowing zero false alarms, and compared at that same false-alarm level.

  • The simple knock generator does not look like real damage in feature space.
  • The curve's floor also mixed in each unit's own false-alarm rate.

WP16FEMTO: how many false alarms per day?

FEMTO records 0.1 s every 10 s. That is too short for fault lines, so only the trend trigger could be tested.

What went into the data spec:

  • at least 30 minutes of healthy baseline per operating state;
  • recordings at least 1 second long;
  • expect about one false trend event per day.

9. What we learned

  1. Physics travels, learned patterns do not. Measurements computed from bearing geometry and speed, and compared with the same machine's healthy data, worked on every new rig. Classifiers trained on one rig failed on others.
  2. A unit's own history is the right reference. Ottawa 2023 went from AUC 0.71 to 0.93. The most common failure everywhere was one unit whose "healthy" data did not look like its own other healthy data.
  3. Small baselines need cross-fitting, or the threshold is too low and false alarms overshoot.
  4. More evidence, taken as a maximum, helps. The geometry-free score (the largest of 135 bins) beat the six named lines on unseen data and in the final exam. Averaging diluted the signal.
  5. No single simple statistic wins everywhere. Kurtosis is great on big faults and useless on subtle ones. Level is a strong trigger at steady speed and needs adjusting when speed and load change.
  6. Detection is solved better than timing. The weak part is the trend alarm across days: it drifts.
  7. Speed must be measured. Estimating it cost 0.14 AUC.
  8. Writing the rule down first kept us honest. Nine pre-registered checks failed, and each one changed the plan.
  9. Infrastructure:
    • Expect blocked services (Kaggle, Google) and keep backup mirrors.
    • Check every file's checksum.
    • Stream data that does not fit.
    • Record exactly which code produced each result.

12. Glossary

Bearing race
The inner and outer rings the balls roll on. Damage on the outer race shows at BPFO, on the inner race at BPFI.
Order
A frequency expressed as a multiple of shaft speed.
Envelope spectrum
The spectrum of the loudness curve of high-frequency vibration. It shows how often knocks repeat.
Baseline
The healthy data a unit is compared with. Own baseline: the same unit. Fleet baseline: other units.
Cross-fitting
Scoring each part of the baseline with a model built without that part, so the threshold is honest.
Conformal threshold
A threshold set from healthy scores so a chosen share (10%) of healthy windows exceed it.
AUC
Chance that a faulty window outscores a healthy one. 0.5 is chance, 1.0 is perfect.
Recall / false alarm
Share of faulty windows caught / share of healthy windows wrongly flagged.
CUSUM
A running sum of how far each recording sits above normal. It alarms on sustained rises.
Run-to-failure
A test where a bearing runs until it breaks, recorded throughout.
Pre-registration
Writing the question and the pass rule down and committing them before running the experiment.
Sealed dataset
A dataset nobody opens until the final exam (IMS here), so it can judge the finished method fairly.
Vault
The permanent 32 GB storage volume, mounted at /mnt/vault on whichever server is rented.
Manifest
The list of every file in a dataset with its size and checksum, kept on the vault and in git.
Geometry-free score
Detection without knowing the bearing: the largest rise over 135 order bins.
Typing hint
Which race's lines rose most. Reported as a hint because it was right only 63–100% of the time across tests.
